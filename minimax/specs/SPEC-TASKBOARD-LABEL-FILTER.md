# SPEC-TASKBOARD-LABEL-FILTER：任务看板的标签筛选

- 规格编号：SPEC-TASKBOARD-LABEL-FILTER
- 状态：已接受（2026-11-04）
- 适用模块：`taskboard.filters`、`taskboard.cli`
- 关联任务：为 MiniMax × OceanBase 赛题完成一次真实、可验证的局部修改

## 1. 背景

任务看板上的每条任务可以带若干标签（`labels`），例如 `backend`、`docs`、
`release`。看板的筛选层目前只支持按状态和负责人筛选，负责人只想看自己那条
线上带 `backend` 标签的任务时，必须在应用层自己再过滤一遍。

## 2. 要改什么

在筛选层增加“按标签筛选”这一条件，并把该条件暴露到命令行。

- `taskboard.filters.filter_tasks` 增加可选参数 `labels`。
- `taskboard.cli` 的 `list` 子命令增加可重复的 `--label` 选项。
- 多个标签之间是“或”的关系：任务的标签集合与给定标签有交集即命中。
- 标签匹配忽略大小写与首尾空白，与 `Task.has_label` 的规则一致。

## 3. 规格条目（可逐条验证）

| 编号 | 条目 |
| --- | --- |
| L-1 | 不给 `labels` 时，筛选结果与改动前完全一致（全部任务，顺序不变）。 |
| L-2 | 给出一个标签时，只返回带该标签的任务。 |
| L-3 | 给出多个标签时，返回带其中任意一个标签的任务。 |
| L-4 | 一条任务带多个标签时，命中其中任意一个即被选中。 |
| L-5 | 标签条件与状态、负责人条件可以同时使用，结果是各条件的交集。 |
| L-6 | 没有任务带某个标签时，返回空列表而不是报错。 |
| L-7 | 标签匹配忽略大小写与首尾空白。 |
| L-8 | 命令行 `taskboard list --label backend` 的输出与库函数一致；`--label` 可重复。 |

## 4. 哪些原有行为必须保持（回归约束）

| 编号 | 原有行为 |
| --- | --- |
| K-1 | 任务身份在看板内唯一；重复身份被拒绝。 |
| K-2 | 标签在任务创建时被去空白并转小写，`has_label` 行为不变。 |
| K-3 | 任务标题、身份不得为空，估计值不得为负。 |
| K-4 | `filter_tasks` 在只给状态或只给负责人时的结果与改动前一致。 |
| K-5 | `group_by_status` 与 `summarize` 的行为不变。 |
| K-6 | 看板的 JSON 存取格式不变。 |

## 5. 验证方式

- 目标测试：`tests/test_filters.py`。
  改动前因 `filter_tasks` 不接受 `labels` 条件而失败，
  改动后全部通过。
- 回归测试：`tests/test_store.py` 与 `tests/test_cli.py`，
  改动前后都必须全部通过。

## 6. 非目标

- 不改变任务的持久化格式，不引入新的依赖。
- 不引入模糊匹配、标签的增删改或标签的层级关系。
